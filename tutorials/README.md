## The remote-code exception, stated up front

This is the one tutorial in the fleet whose model **cannot** be loaded with `trust_remote_code=False`: `config.json`
declares `model_type: "molformer"`, for which the installed Transformers has no native implementation, and the
linear-attention architecture exists only in the upstream `modeling_molformer.py`. The notebook therefore executes two
upstream Python files — and both are **snapshot manifest entries**, verified by SHA-256 before they are imported;
`verify_snapshot` refuses a manifest that omits them. `tools/validate_release_assets.py` enforces that
`trust_remote_code=True` appears **only** inside the carried module cell and nowhere else in the notebook, that the
manifest lists both files, and that verification precedes the model-library import. This narrows the boundary; it does
not remove it, and the notebook says so where a reader will see it. The DIMER hosting consequence is recorded in
`../MODEL_CARD.md` (*DIMER deployment notes*).

## Conformance notes

- **Standalone carrier (ST1–ST8):** the primary path performs no clone, repository install, or repository import. Section 2 embeds the repository's 3 modules (`pipeline.py`, `samples.py`, `metrics.py`) verbatim in topological dependency order (each tagged `metadata.dimer.embedded_module`; the only rewrites make `DEFAULT_WEIGHTS_DIR` working-directory-relative and remove internal relative package imports), Section 3 carries the 7-file snapshot manifest inline and asserts it against the module's own identity constants before anything is fetched, and Section 1 carries the exact `pyproject.toml` runtime pins. `metadata.dimer.generated_from` records the repository, the revision, the module SHA-256 digests, and the generator version.
- **Parity (PAR1–PAR4):** `tests/test_notebook_parity.py` and `tools/validate_release_assets.py` fail when the carried modules, the inline manifest, or the inline pins differ from the repository, or when the notebook is not byte-identical to the generator's output.
- **Model acquisition (MOD1–MOD9):** `stage_missing_files(WEIGHTS_DIR, allow_download=True)` fetches only the manifest entries that are absent, from the Hugging Face Hub at the immutable revision (never `main`); `verify_snapshot` re-hashes every entry **including the two Python files**; `MolformerPipeline.from_pretrained(weights_dir=...)` then loads the tokenizer with `trust_remote_code=False` and the model with `local_files_only=True`, `use_safetensors=True`, `deterministic_eval=True` and `trust_remote_code=True`. There is no `pytorch_model.bin` at the pinned revision, so no pickle is a load candidate (MOD9). The notebook never imports `transformers`, `huggingface_hub` or `safetensors` for model work outside the carried module cells.
- **Runtime pin divergence (RUN2):** Section 1 installs `transformers==5.17.0`, not the fleet's 4.57.6, and says why — the pinned upstream code calls `transformers.masking_utils.create_bidirectional_mask(inputs_embeds=...)`, whose current signature exists from Transformers 5.5.0. The stale-import guard applies as usual.
- **Stages (§4.1):** `generate_sample_dataset` / `load_byod_dataset` (sample acquisition) → `validate_dataset` (validation, with the ceilings, the shared-formula count and a dataset digest) → `split_dataset` (stratified train/validation/test) → `pipe.embed` (representations, with a repeated-call determinism assertion) → `majority_baseline` + `formula_baseline` (baselines fitted on the training split only) → `pipe.adapt` (bounded gradient fine-tuning, real on the default path, RUN7/FT2) → `pipe.evaluate` (held-out metrics) → `pipe.classify` (new-data inference) → `pipe.save_artifact` (export + provenance + serving state) → `MolformerPipeline.from_artifact` (fresh-boundary reload and parity assertion).
- **Score semantics (UNC1–UNC4):** the per-class scores are softmax outputs of a head trained on a small labelled set, not calibrated probabilities; the only decision rule is argmax, and deployment thresholding is the caller's. Embeddings are labelled as representations with no intrinsic metric (EVAL9); the notebook states what a downstream labelled task would be needed for.
- **Determinism (UNC5):** with upstream's `deterministic_eval: false` the linear-attention random features are redrawn on every forward pass and repeated inference on the same molecule differs. The notebook loads with `deterministic_eval=True`, prints the setting, and asserts that a second `embed` call returns the identical vector. During `adapt` the features **are** redrawn (upstream's intended stochastic regularisation), which is why the exported adapter carries the 12 `.feature_map.weight` buffers as declared serving state; without them the reload parity is 0.0023 instead of 0.0.
- **Baselines and evidence (EVAL6/EVAL10/EVAL11):** majority-class and molecular-formula baselines are computed on the same test split as the model, and every metric is labelled as tutorial sample-sanity evidence from one seeded holdout with no dispersion estimate. The two synthetic classes are **constitutional isomers** — the notebook asserts that a linear and a branched example share a molecular formula, and the dataset manifest reports how many formulas appear in both classes — which is what makes the comparison informative: a model that has only learned composition cannot beat chance here.
- **Split integrity (SPL1–SPL8):** the split is explicit, stratified and seeded; validation metrics are used for per-epoch monitoring only and the final epoch's weights are kept, so the test split is never used for selection. The notebook states that random splitting assumes independent records and that **analogues sharing a scaffold across splits leak** — the chemistry-specific form of the same hazard, which scaffold or cluster splitting addresses and which this pipeline cannot detect for you.
- **Ceilings (VAL6):** `MAX_TOKENS = 200` (a longer molecule is refused, not truncated), `MAX_POSITION_EMBEDDINGS = 202`, `MAX_MOLECULES_PER_CALL = 64`, the record and class minimums and maximums, and the accepted SMILES character set are printed from the dataset manifest before the model runs. The notebook is explicit that SMILES validation here is **syntactic only** — no cheminformatics toolkit ships with this repository, and no canonicalisation or standardisation is performed.
- **BYOD (DAT10–DAT19):** `USE_BYOD` defaults to `False` so the sample path never opens an upload dialog; when enabled, user data flows through the same validation, split, baselines, adaptation, evaluation, inference, export and reload cells. The expected schema and the privacy guidance are stated in the Prerequisites and in Section 4 — including that a hosted runtime is the wrong place for an unpublished structure — and the sample dataset is written to `outputs/molformer_chemistry_sample_dataset.csv` as a template.
- `tools/validate_release_assets.py` performs source validation only. It does not satisfy the clean-runtime execution requirement; a release review must confirm that a recorded clean run in `../docs/release-verification.md` matches the notebook revision under review before the status is promoted to `Release-grade`.
